# تقرير إقفال وكيل إدارة المحتوى

**المشروع:** AdminStudentWeb — أكاديمية مسار  
**النطاق:** وكيل إدارة محتوى داخل لوحة الإدارة فقط  
**حالة التقرير:** مكتمل بعد اختبار End-to-End والتنظيف النهائي  
**التاريخ:** 29 أغسطس 2026

## الخلاصة التنفيذية

اكتمل توسيع `admin-ai` من محادثة إدارية إلى **وكيل إدارة محتوى مقترِح**. يستطيع الوكيل تحليل طلبات الإدارة وروابط YouTube وملفات المحتوى المنظمة، ثم إنتاج مسودة قابلة للمراجعة. لا ينشئ الوكيل أو يعدّل أو يحذف أو ينشر محتوى تلقائياً؛ فالعملية الخادمية مقيدة دائماً بتوثيق المستخدم، والتحقق من دور الإدارة، والتحقق النهائي من البيانات، ثم اعتماد صريح وتنفيذ منفصل.

يحافظ التنفيذ على القيود المطلوبة: **لا يوجد YouTube Data API أو مفتاح YouTube أو تنزيل فيديو أو تخزين فيديوهات**. تُستخرج معرّفات الفيديو محلياً من روابط YouTube الصحيحة فقط، ويقتصر جلب البيانات العامة على HTML محدود ومتحفظ. كما لم يُعدّل تطبيق الطالب ضمن هذه المرحلة.

| المجال | النتيجة |
|---|---|
| Edge Function | `admin-ai` نشطة، الإصدار **29**، مع `verify_jwt=true` |
| دورة المحتوى | `analyze → approve → execute` مع `update_draft` و`cancel` |
| العمليات المدعومة | استيراد، تعديل، حذف، نشر، وإلغاء نشر عبر Draft منفصل |
| صيغ الملفات | CSV وXLSX وJSON وTXT وMarkdown، بحد أقصى 2 مرفق و2MB و200 صف |
| سلامة المحتوى الحالية | **2 كورس** و**1 درس**؛ لم تُنشأ بيانات محتوى جديدة أثناء اختبارات الإقفال |
| بوابات الجودة | TypeScript وLint والاختبارات وبناء الويب ناجحة |

## ما نُفذ

أُعيد تنظيم Edge Function في وحدات مهارية مستقلة تغطي معرفة المنصة وتصنيف الطلبات واستخراج YouTube وتحليل الملفات والتحقق والموافقة وبناء إجراءات المحتوى. وتدعم الوظيفة تصنيفات `CHAT` و`PLATFORM_READ` و`EXTERNAL_URL` و`YOUTUBE_VIDEO` و`YOUTUBE_PLAYLIST` و`COURSE_IMPORT` و`COURSE_UPDATE` و`COURSE_DELETE` و`PUBLISH` و`MIXED`.

المصدر التنفيذي موجود في `supabase/functions/admin-ai/`، بينما تعرض `components/admin-ai-chat.tsx` واجهة محادثة إدارية فيها إرفاق ملفات، ومعاينة منظمة للمسودة، وتحرير محدود لعنوان ووصف الكورس، وأزرار اعتماد وتنفيذ وإلغاء منفصلة. وتبقى أزرار التنفيذ محكومة بحالة المسودة وليس بمجرد نص المحادثة.

| العنصر | التنفيذ الفعلي |
|---|---|
| المصادقة | تتحقق الوظيفة من JWT ثم من `admin_profiles.role='admin'` قبل قراءة المنصة أو إنشاء Draft أو الاتصال بالنموذج |
| المسودات | جدول `content_agent_drafts` يحفظ الحمولة المنظمة والحالة والانتهاء ومالك المسودة وبصمة التنفيذ |
| سجل التدقيق | جدول `content_agent_audit_logs` يسجل التحليل والاعتماد والتنفيذ والرفض والفشل والإلغاء من دون أسرار أو JWT |
| منع التكرار | فحص داخل المسودة، وفحص فيديوهات الكورس، وقيد فريد لفيديو الدرس داخل الكورس، وفهرس Playlist عند وجود المعرّف |
| التنفيذ | الخادم يعيد التحقق من الحالة والملكية والبيانات والاعتماد قبل أي عملية كتابة |
| التعافي | التنفيذ المتكرر لمسودة منفذة يرفض برسالة دقيقة بدلاً من إعادة العملية |

## تعديلات التقوية أثناء الإقفال

تمت معالجة ثلاث نقاط ظهرت أثناء الاختبار. أولاً، إذا أعاد النموذج المحدد في إعداد الخادم خطأ `400`، تجرب الوظيفة النموذج الاحتياطي `openai/gpt-4o-mini` قبل إرجاع الخطأ؛ وقد أعاد ذلك نجاح قراءة بيانات المنصة عند فشل النموذج المهيأ. لا يتجاوز هذا المسار أخطاء التوثيق أو حدود الاستخدام.

ثانياً، أصبح استخراج `Video ID` و`Playlist ID` مقيداً حصراً بنطاقات `youtube.com` و`youtu.be`. لذلك لا يمكن لرابط خارجي يحمل معامل `v=` أن يتحول إلى درس YouTube. وثالثاً، إذا وُجد الفيديو نفسه أكثر من مرة في مصدر الاستيراد، يُحذف التكرار من المسودة مع تحذير ظاهر بدلاً من إضافة درس مكرر صامتاً.

كما عُولج تنبيه أمني حقيقي في `public.is_admin()`: الدالة تعمل الآن بـ`SECURITY INVOKER` وتقرأ ملف المستخدم نفسه عبر سياسة RLS القائمة، فلا تحتاج إلى `SECURITY DEFINER`. وبعد الترحيل لم يبقَ في تدقيق الأمان سوى تنبيه إعداد مستقل في Supabase Auth يتعلق بتعطيل **حماية كلمات المرور المسرّبة**.

## نتائج الاختبار

أُجريت اختبارات تحليل فقط وعمليات تحقق تمنع الكتابة. أما اختبار الإنشاء والحذف السابق فقد تم ضمن موافقة صريحة سابقة، ثم أزيل المحتوى التجريبي بنجاح. لم يُنفذ اختبار تحديث أو نشر أو حذف على محتوى حقيقي في مرحلة الإقفال، التزاماً بشرط عدم تعديل المحتوى من دون موافقة مستقلة.

| حالة الاختبار | النتيجة | الملاحظة |
|---|---|---|
| قراءة المنصة بواسطة Admin | ناجح | تحقق دور الإدارة ونجح الرد بعد fallback للنموذج |
| استدعاء بلا جلسة | مرفوض | حماية JWT تمنع الوصول قبل التحليل أو الكتابة |
| تنفيذ Draft غير معتمدة | ناجح | رُفض بـ`409 draft_state_invalid` من دون تغيير الحالة أو المحتوى |
| محاولة تنفيذ Draft منفذة سابقاً | ناجح | الرفض قائم ورسالة الحالة أصبحت دقيقة |
| رابط نطاق غير YouTube يحمل `v=` | ناجح | صُنّف `EXTERNAL_URL`، بصفر دروس ومن دون Draft |
| رابط YouTube مع حظر خارجي `429` | ناجح بتحفظ | حُفظ Video ID محلياً ولم تُخترع بيانات وصفية |
| CSV على الخادم | ناجح | بُنيت Draft من صفين ثم أُلغيت من دون إنشاء محتوى |
| منتقي ملفات الويب | ناجح | قبل CSV وJSON وXLSX وTXT وMarkdown محلياً قبل الإرسال |
| منع تكرار الفيديو | ناجح | تغطيه اختبارات Skills والتحقق الخادمي |
| اختبارات الوحدات | ناجح | 6 اختبارات ناجحة، و2 متخطاة قصداً |
| فحص النوع وLint وبناء الويب | ناجح | `pnpm check` و`pnpm lint` و`pnpm test` و`pnpm build:web` مرت جميعها |

> الاختبار الحي لمفتاح OpenRouter أصبح اختيارياً ويعمل فقط عند ضبط `RUN_OPENROUTER_INTEGRATION_TEST=true`، حتى لا تُفسَّر مشكلة اتصال خارجي مؤقتة على أنها فشل في المشروع. اختبار الإعداد المحلي لا يعرض المفتاح.

## حالة البيانات والمسودات

بعد اختبارات الإقفال بقيت جداول المحتوى التعليمية عند **كورسَين ودرس واحد**. وآخر مسودة أُنشئت للاختبار كانت `cancelled`. توجد أيضاً مسودة استيراد قديمة بحالة `draft` ما زالت ضمن مدة صلاحيتها؛ لم تُعتمد أو تُنفذ أو تُلغَ نيابة عن الإدارة. ينبغي أن يقرر Admin الاحتفاظ بها أو إلغاؤها من واجهة الوكيل عند المراجعة.

## الأمان والخصوصية

يُحفظ مفتاح OpenRouter في أسرار Edge Function من جانب الخادم فقط، ولا يوجد `OPENROUTER_API_KEY` أو `SUPABASE_SERVICE_ROLE_KEY` أو مفتاح Supabase سري في شجرة العميل (`app/` و`components/` و`lib/`). لا تظهر الأسرار أو ترويسات Authorization أو JWT أو نص المحادثة الكامل في سجل التشخيص.

| طبقة الحماية | الضبط الحالي |
|---|---|
| الوصول للوظيفة | JWT مطلوب، ثم فحص دور Admin |
| الكتابة | خادمية فقط وبعد اعتماد صريح وتحقق نهائي وبصمة idempotency |
| الشبكة الخارجية | HTTPS فقط، حظر عناوين محلية/خاصة بالاسم، 3 redirects كحد أقصى، 12 ثانية، و1MB |
| YouTube | لا API ولا API Key ولا تنزيل ولا CAPTCHA ولا تجاوز تسجيل الدخول |
| RLS | مطبق على Drafts وAudit Log مع ملكية المسودة وصلاحية Admin |

## القيود المتبقية

الحماية الحالية للطلبات الخارجية جيدة كحاجز أولي، لكنها لا تحل اسم المضيف إلى عنوان IP قبل الطلب؛ لذلك يظل تقوية فحص DNS/IP ضد DNS rebinding تحسيناً مستقبلياً مستحسناً. كذلك فإن تنفيذ استيراد الكورس ليس معاملة SQL واحدة كاملة؛ يعالج فشل إنشاء الدروس بحذف الكورس المنشأ، لكنه يحتاج ترقية مستقبلية إلى RPC/معاملة ذرية إذا كبرت أحجام الاستيراد أو زادت المنافسة.

يبقى تحليل Playlist من HTML عام، ولذلك قد يفشل أو يعيد `429` من YouTube. عندها يحافظ الوكيل على ما يمكن إثباته محلياً ويعرض تحذيراً؛ لا يخمن عنواناً أو وصفاً أو عدد فيديوهات. ولم تُنفذ ميزة Transcript لأنها اختيارية وتتطلب مصدراً مسموحاً. أما إخراج النموذج فهو مقيد بتعليمات وخادم تحقق، وليس JSON Schema صارماً من المزود الخارجي.

## التوصيات التالية

1. يوصى بتفعيل **Leaked Password Protection** من إعدادات Supabase Auth؛ وهو تنبيه الأمان الخارجي الوحيد المتبقي بعد معالجة `is_admin`.
2. عند الموافقة لاحقاً، يوصى باختبار تحديث/نشر/إلغاء نشر على نسخة تجريبية غير مرئية أو محتوى محدد يوافق عليه Admin صراحةً.
3. في دورة تقوية لاحقة، يوصى بنقل تنفيذ الاستيراد إلى عملية ذرية وتحسين حماية DNS للطلبات الخارجية.
4. يوصى بإضافة عرض للـDiff على مستوى الدروس وتحرير مفردات الدروس في المسودة، إذ يتيح الإصدار الحالي تعديل عنوان ووصف الكورس فقط.

## القرار المقترح

الوكيل جاهز للاستخدام الإداري المقيد: التحليل وإنتاج المسودة والمراجعة والاعتماد والتنفيذ الخادمي متاحة ضمن الضوابط المذكورة. لا يوصى بإزالة أي حاجز موافقة، ولا بتنفيذ عمليات على المحتوى الحقيقي آلياً. قبل تشغيله على استيرادات كبيرة، ينبغي معالجة تحسين المعاملة الذرية وحماية DNS كمرحلة تقوية مستقلة.


## ملحق اختبار End-to-End الفعلي — 29 أغسطس 2026

أُجري الاختبار بعد موافقة المستخدم الصريحة على إنشاء محتوى تجريبي مخفي والتحقق منه ثم حذفه بالكامل. استُخدم الهدف الأكاديمي الموجود فعلياً: **الخامس الابتدائي → رياضيات → احمد علي**، بمعرّف Teacher Assignment يساوي `da40b17c-1e6b-45cf-ad27-cc4db58c3b7c`. لم تُنشأ كيانات أكاديمية جديدة، ولم يُمس Course حقيقي.

| نقطة القياس | القيمة قبل الاختبار |
|---|---:|
| إجمالي الكورسات | 2 |
| إجمالي الدروس | 1 |
| الكورس المحمي | C++، المعرّف 1 |
| الدرس المحمي | الدرس الأول، المعرّف 1 |
| الهدف الأكاديمي | الخامس الابتدائي / رياضيات / احمد علي |

### المصدر وfallback

تعرّف النظام على رابط Playlist تجريبي كـ YouTube Playlist، لكن جلب HTML العام أعاد `external_http_429`. لم يستخدم الوكيل YouTube Data API، ولم يحاول تجاوز حماية YouTube أو تسجيل الدخول. أُلغيت المسودة الناتجة لأنها لم تحتوي Teacher Assignment مطابقاً ولا دروساً صالحة. بعد ذلك استُخدم fallback مسموح من رابطَي فيديو YouTube عامين، فاحتفظ النظام بمعرّفي الفيديو محلياً رغم فشل قراءة metadata الخارجية.

نتيجة fallback كانت Draft صالحة بعدد درسين: `dQw4w9WgXcQ` بترتيب 1 و`9bZkp7q19f0` بترتيب 2. بقي العنوانان مشتقين (`الدرس 1` و`الدرس 2`) والوصفان غير متاحين، ولم تُخترع أي metadata.

### Draft وApproval وExecute

أُنشئت المسودة `0f0f3d42-da75-4020-8bb2-897693597643` بحالة `draft` و`valid=true`. محاولة Execute قبل Approval رُفضت بـHTTP `409` والرمز `draft_state_invalid`. بعد Approval صريح أصبحت الحالة `approved` و`execution_enabled=true`، ثم أُنشئ Course تجريبي بالمعرّف 4، ودرسان بالمعرّفين 3 و4، وجميعها `is_published=false`.

أظهر التحقق أن Course 4 يحمل Teacher Assignment الموجود، وأن الدروس تحمل Video IDs والروابط والترتيب الصحيح. أُعيدت محاولة Execute للمسودة نفسها، فتم رفضها بـHTTP `409` والرسالة الدقيقة التي تفيد بأن المسودة نُفذت سابقاً؛ لم يحدث تكرار.

### إصلاح Draft الحذف

فشل إعداد Draft الحذف الأول لأن محلل الإجراء كان يعتمد على آخر خمسة مصطلحات من النص ولم يلتقط Course التجريبي بالعنوان أو الرقم. أُلغيت Draft غير الصالحة، ثم أُضيف دعم محدود لاستخراج Course ID الصريح (`رقم 4` أو `id 4`) داخل `resolveActionCourse`. هذا الإصلاح لا ينفذ الحذف تلقائياً، ولا يزيل Approval أو Admin check أو التحقق النهائي.

بعد نشر `admin-ai` بالإصدار **29**، أُنشئت Draft الحذف `50ed8331-3c20-442e-bc22-ded0ce7369d8` وكانت مرتبطة صراحةً بـCourse 4. اعتمدت المسودة ثم نُفذت، فحُذف Course 4 ودروسه المرتبطة عبر الوكيل فقط. لم يُستخدم SQL مباشر لحذف المحتوى.

### التحقق النهائي

بعد الحذف لم يعد Course 4 أو الدرسين 3 و4 موجودين. بقي Course C++ والدرس الأول دون تغيير: Course 1 ظاهر، والدرس 1 ظاهر، وVideo ID الخاص به `XDuWyYxksXU`. أظهر العد النهائي 2 كورسات، و1 درس، و2 كورسات ظاهرة، و1 درس ظاهر، و0 كورسات مخفية، و0 دروس مخفية.

| فحص القبول | النتيجة |
|---|---|
| Playlist extraction | فشل متحفظ بـ429، دون bypass |
| Fallback Video IDs | محفوظة محلياً وصحيحة |
| Academic target | مطابق للـTeacher Assignment الموجود |
| Preview/Draft | صالح، درسان، ترتيب 1 و2، دون metadata مختلقة |
| Execute قبل Approval | مرفوض 409 |
| Execute بعد Approval | أنشأ Course 4 مخفياً وLessons 3 و4 مخفية |
| Execute للمرة الثانية | مرفوض 409، دون تكرار |
| Delete | حذف Course 4 وLessons المرتبطة عبر Draft معتمدة |
| المحتوى الحقيقي | C++ والدرس 1 بقيا دون تغيير |
| الحالة النهائية | 2 Courses، 1 Lesson، ولا محتوى مخفي |

### Audit والأمن

سجل Audit للمسودة الأولى `analyzed → approved → executed` مع Course ID 4، وسجل Draft الحذف `analyzed → approved → executed` مع `resource_id=4`. لم تتضمن السجلات مفتاح OpenRouter أو Authorization header أو JWT أو كلمات مرور أو نص المحادثة الكامل. بقي `verify_jwt=true` في الإصدار المنشور.

تم أيضاً التحقق من أن تنفيذ Course ID الصريح لا ي bypass أي حاجز: لا تزال الوظيفة تتطلب جلسة JWT وAdmin profile، وتقرأ Draft المملوكة، وتتحقق من الحالة قبل التنفيذ. وتظل حماية المصادر الخارجية محدودة بـHTTPS وحظر المضيفات الخاصة وحدود redirect والمهلة والحجم. لا يزال DNS/IP resolution الكامل ضد DNS rebinding تحسيناً مستقبلياً.

### نتيجة الإقفال

نجح اختبار End-to-End الكامل: **Playlist attempt → fallback → Analysis → Draft → رفض Execute غير المعتمد → Approval → Execute مخفي → Verify → رفض التكرار → Draft حذف → Approval → Delete → Final Verify**. لم تُضف ميزة جديدة ضمن الاختبار، ولم تتغير Schema أو Student App أو Skills، ولم يُستخدم YouTube Data API. بعد هذه الإضافة لا توجد عملية محتوى أخرى مطلوبة ضمن الطلب، ويجب التوقف عند التقرير.
